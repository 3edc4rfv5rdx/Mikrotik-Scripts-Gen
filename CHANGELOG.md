# Changelog

## [Unreleased]

- `dual-wan-failover.md` is now in English, with the Russian original in `dual-wan-failover.ru.md`.
- Added short README files for the repository and each generator.
- Repository renamed to Mikrotik-Scripts-Gen; each generator lives in its own folder, `WireGuardGen/` and `DualWanGen/`.
- A tunnel address that is the network or broadcast address of its subnet is rejected (up to /30).
- Ports with leading zeros are read as decimal and written to the `.rsc` without them.
- The note on keeping `:local` inside `{ }` moved from the generated `.rsc` into the generator source.
- `DualWanB.conf` refreshed to the restyled sample.
- `dual-wan-failover.md` walks through the path of a packet over the primary uplink.
- The `DualWanB.sh` header warns that a re-import leaves the router without a default route for a few seconds.
- `DualWanB.sh` waits 2s before the foreign default-route check when it took over a DHCP client, so its vanishing route is not reported.
- `DualWanB.sh` refuses the same interface for both uplinks.
- The `DualWanB.sh` sample comments every parameter, spaces them out and marks WAN 1 / WAN 2 with banners.
- The `DualWanB.sh` undo finds taken-over DHCP clients by the tag in their script, whatever the current config says.
- The `DualWanB.sh` undo header says it also hands back the DHCP clients it took over.
- The foreign default-route warning only counts enabled routes in `main`, so policy-routing tables no longer trigger it.
- RouterOS locals in the generated files live inside `{ }` blocks, so nothing relies on `/import` keeping a top-level `:local` between lines.
- `WAN*_GATEWAY=dhcp` takes over the DHCP client on `WAN*_IFACE`: no own default route, and a lease script that keeps the probe route on the current gateway.
- The `DualWanB.sh` sample keeps the `add-default-route=no` note as its own block instead of under `ROUTER`.
- `DualWanB.sh` sample notes that the probe address is reachable only through its uplink.
- `DualWanB.sh` validates the gateways and requires `WAN1_DISTANCE` below `WAN2_DISTANCE`.
- `DualWanB.sh` explains why foreign default routes break failover and warns at import when one is present.
- `DualWanB.sh --example` writes the sample to the config file, moving an existing one to `.bak`.
- `DualWanB.sh` cleanup matches the tag anchored as `^<tag> `, so `home` no longer catches `home2`.
- `dual-wan-failover.md` explains fail-back, why the probe is the gateway, dropped masquerade sessions and scope in plain words.
- The sample leaves `A_IFACE`/`B_IFACE` empty, so they default to `wg-<peer name>`.
- Endpoint comments in the sample say whose address it is: the router itself, dialled by the peer.
- `*_ENDPOINT`, `MTU` and `KEEPALIVE` are validated before generation instead of failing at `/import`.
- Output files carry both names, own first (`sideA-<A>-<B>.rsc`), so a hub router gets one file per tunnel.
- Cleanup matches the tag anchored as `^<tag> `, so one tunnel no longer catches another whose name extends it.
- The sample config marks side A and side B with `#` banners.
- `wg-gen.conf` refreshed to the current sample; `*.bak` is git-ignored.
- Private keys are always generated; `A_PRIVATE_KEY`/`B_PRIVATE_KEY` are gone from the config.
- `PRESHARED_KEY` replaced by a `PSK=yes|no` flag; a supplied key is no longer accepted.
- The side file always removes every tagged menu, so switching firewall or routes off leaves nothing behind.
- The emitters take the side letters and read their settings through namerefs instead of 13 positional arguments.
- Keys are generated through openssl only; the `wg` branch is gone.
- Dropped the forward accept rules; `*_FIREWALL` now emits only the input rule for the listen port.
- Removed `A_CHECK_GATEWAY`/`B_CHECK_GATEWAY`: without a backup path to the same networks they only leak traffic to the default route.
- The sample config puts a blank line after every parameter.
- Each side tags its objects with its own name first: `wg-gen: <own>-<peer>`.
- Shared `PORT` for both sides, with `A_PORT`/`B_PORT` as per-side overrides; every sample parameter is commented.
- `--example` writes the sample to the config file, moving an existing one to `.bak`.
- Generated `out-*/` directories are git-ignored, since they hold private keys.
- Added `DualWanB.sh`: generates the dual-WAN failover `.rsc` (recursive probes, two defaults with `check-gateway=ping`, optional masquerade) plus its undo file.
- Probe addresses are 8.8.4.4 and 1.0.0.1, in the script and in the note.
- Separate `removeA-`/`removeB-` files undo an import: they drop every tagged object, whatever the side was generated with.
- Added `dual-wan-failover.md`: recursive-route failover between two uplinks under one tunnel.
- Routes use the peer's tunnel IP as gateway, with optional `check-gateway=ping` via `*_CHECK_GATEWAY`.
- WireGuard peers get a `name` of `peer-<other side>`.
- The generated `.rsc` removes itself by name pattern, so it also works when the file sits in `flash/`.
- Per-side routing: `A_ROUTE_TO_B` / `B_ROUTE_TO_A` list the networks routed into the tunnel.
- Firewall rules are emitted `disabled=yes`, and the input rule is placed before the defconf LAN drop found by its properties instead of `move`.
- Output files are named `sideA-<A_NAME>.rsc` / `sideB-<B_NAME>.rsc`.
- Renamed to `wg-gen.sh` / `wg-gen.conf`; RouterOS objects are tagged `wg-gen: <A>-<B>`.
- Output goes to `out-<A_NAME>-<B_NAME>` and the input config is copied next to it.
- Generated `.rsc` removes itself from the router after import, since it carries the private key.
- The firewall cleanup line is emitted only on a side that manages firewall rules.
- Generator `wg-gen.sh`: builds a pair of RouterOS `.rsc` files for a WireGuard site-to-site tunnel from one config file, with optional per-side firewall rules.
